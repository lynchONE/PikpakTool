# PikpakTool

PikPak 网盘年份整理工具，支持本地网页和 Chrome 扩展。全盘递归扫描，按添加年份归档大文件，批量清理同名重复、小文件和空目录，并保存任务进度以便中断后恢复。

## 整理规则

- 严格大于 **100,000,000 字节（100MB）** 的文件，按添加时间的北京时间年份归入网盘根目录 `/YYYY/`。
- 同一年份、完全相同文件名只保留一份：优先已在目标年份目录中的文件，其次体积更大、添加时间更早、ID 字典序更小。此规则不是内容指纹去重。
- 小于或等于 100MB 的文件以及重复组中的非保留项移入回收站，不永久删除。
- 元数据异常的项目跳过，其他正常项目继续执行。空目录实时判空，按层级从内到外清理。
- 默认每批最多 50 个文件、2 批并发。正常执行不逐文件前后核验，只跟踪 PikPak 的整批异步任务结果。

## 本地运行

需要 Node.js 20 或更新版本。运行时没有第三方依赖。

```powershell
git clone https://github.com/lynchONE/PikpakTool.git
cd PikpakTool
npm start
```

Windows 也可双击项目根目录的 `start-local.cmd`。打开：

**http://127.0.0.1:8788/task.html**

在 PikPak 的「账号与安全 → 已连接的应用 → 个人访问令牌」创建具有「管理文件」权限的令牌，在工具中连接、扫描并审阅计划后执行。工具只监听本机地址；关闭运行进程会停止本地服务。

## Chrome 扩展

1. 打开 `chrome://extensions` 并启用开发者模式。
2. 点击「加载已解压的扩展程序」，选择项目根目录或构建后的 `dist` 目录。
3. 点击扩展图标，再点击「打开整理工具」。

本地版通过 Node.js 请求 PikPak，扩展版直接请求 PikPak。两种模式共用同一套规则、批量执行和恢复代码。

## 暂停与恢复

扫描后自动保存计划，批次提交前后保存检查点。刷新或重启后，使用同一令牌连接，页面会自动恢复保存的任务，点击「继续未完成批次」。

- 已完成批次不会重复提交。
- 已有远程任务编号的批次继续查询整批状态。
- 尚未提交的批次继续提交。
- 提交结果未知的批次仅定位实际状态，不能确认时不自动重发。
- 重新扫描会创建新任务，并替代同一令牌的旧活动计划。

计划、操作记录和不可逆令牌指纹保存在浏览器 IndexedDB；**令牌本身只驻留内存，不写入文件或日志**。清除站点数据会丢失本地任务。任务存储按浏览器和页面来源隔离：本地地址及端口保持不变时，移动项目目录不会改变本地任务存储。

扫描和执行均显示进度、速度、已用时间和预计剩余时间。扫描总量随着新目录发现动态调整，剩余时间是估算值。

## 开发与构建

```powershell
npm ci
npm test
npm run build
npm run benchmark
```

源码位于项目根目录，测试位于 `test/`，构建只复制运行所需文件到 `dist/`。`fake-indexeddb` 仅用于开发测试。

| 文件 | 用途 |
| --- | --- |
| `core.mjs` | 全盘扫描、规则规划、进度计算 |
| `batch.mjs` | 批量执行、任务依赖、恢复处理 |
| `api.mjs` | PikPak 文件 API |
| `local-api.mjs` | 本地网页与本机服务通信 |
| `journal.mjs` | IndexedDB 日志和任务存储 |
| `scripts/local-server.mjs` | 回环 HTTP 服务 |
| `task.html` / `task.mjs` | 工具界面 |

更多内容见 [设计说明](docs/design.md)、[需求](docs/requirements.md) 和 [验证说明](docs/validation.md)。

## 使用边界

- 依赖 PikPak 当前接口及个人令牌权限；接口拒绝或格式变化时会显示错误并保留待处理状态。
- 添加时间使用原始 `created_time` 字段，首次执行前请与 PikPak 页面显示对照。
- 执行按已确认的文件 ID 清单处理，不重新全盘扫描。整理期间应暂停其他客户端对同一批文件的改动。
- 目录判空与删除不是原子操作；工具不承诺跨客户端事务保证。
- 自动化测试使用模拟文件与 HTTP 服务，不会操作真实用户网盘。
